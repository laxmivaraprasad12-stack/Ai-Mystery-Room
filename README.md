# AI Mystery Room

A guest-first, single-player browser mystery game. Players provide a fictional premise, investigate a Gemini-generated case, and make one final accusation. The client never receives the solution until the server has accepted the guess.

## Requirements

- Node.js 20 or newer and npm
- MongoDB 7 or newer (local or hosted)
- A Gemini API key for case generation

## Run locally

1. Install dependencies from the repository root:

   ```powershell
   npm install
   ```

2. Set `GEMINI_API_KEY` in `server/.env` (recommended) or the repository-root `.env`. The server loads both, with `server/.env` taking precedence. You can copy the template with:

   ```powershell
   Copy-Item .env.example server/.env
   ```

   Set `MONGODB_URI` if MongoDB is not running at the local default. For any shared or deployed environment, replace `SESSION_SECRET` with a long random value.

3. Start a local MongoDB with Docker (or use your own MongoDB instance):

   ```powershell
   docker compose up -d mongo
   ```

4. Start the API and Vite client:

   ```powershell
   npm run dev
   ```

   Open `http://localhost:5180`. Vite proxies `/api/v1` to the API on port 4000, so the browser uses one origin and the guest cookie works locally. Health is available at `http://localhost:5180/api/v1/health`.

5. Create a production build with `npm run build`. In production the Express server serves `client/dist` and the API from the same origin, which keeps guest cookies and API requests together.

## Publish on Render

This repository includes a `render.yaml` Blueprint for one Node web service. The service builds both workspaces, serves the React app from Express, and exposes the API under the same domain. You do not need a separate static-site service or `VITE_API_URL` for this setup. Render documents [Express web services](https://render.com/docs/deploy-node-express-app) and [Blueprints](https://render.com/docs/infrastructure-as-code).

1. Push this repository to GitHub. Confirm that neither the root `.env` nor `server/.env` is tracked; both are ignored. Never commit your Gemini key or database password.
2. In Render, create a new Blueprint from the GitHub repository and apply `render.yaml`. Render creates a web service and asks you for `MONGODB_URI` and `GEMINI_API_KEY`. Add the Atlas URI and Gemini key there as secret environment values. Render makes configured environment variables available to the service at runtime and can redeploy after they change; see [Render environment variables](https://render.com/docs/configure-environment-variables).
3. In Atlas, use a **database user** in the URI (not your Atlas website login), confirm the password and cluster hostname, and add the Render service’s outbound IP addresses to the Atlas project IP access list. Atlas requires both valid database authentication and an allowed client IP; see [connection troubleshooting](https://www.mongodb.com/docs/atlas/troubleshoot-connection/) and [IP access lists](https://www.mongodb.com/docs/atlas/security/add-ip-address-to-list/).
4. Keep `SESSION_SECRET` generated by the Blueprint and `COOKIE_SECURE=true`. Render provides `PORT`; the server binds to it on `0.0.0.0`. If you attach a custom domain, set `CLIENT_ORIGIN` to its exact HTTPS origin in the service environment.
5. After deployment, open `https://YOUR-SERVICE.onrender.com/api/v1/health` and expect `{ "data": { "status": "ok" } }`. Then open the service root URL to use the game.

The local `server/.env` points to your computer’s MongoDB and is ignored by Git. It is not the production database. The Render environment’s `MONGODB_URI` takes precedence over dotenv files.

## Product and implementation choices

- **Guest sessions:** the server issues a random, signed, HTTP-only, SameSite=Lax cookie. Case ownership is checked on every case read, guess, retry, and delete. The cookie is not exposed to JavaScript. Guest records expire 30 days after creation by default; change `GUEST_RETENTION_DAYS` to adjust MongoDB TTL retention.
- **Investigation progress:** reviewed evidence IDs are stored on the owned case and restored when a player reopens it. Players can still guess without reviewing all evidence.
- **Text-first evidence:** evidence uses readable text and structured cards. Image evidence is represented by a text description; the MVP does not generate or store image/video media.
- **Generation:** Gemini calls are server-only, use a configurable model and timeout, and return a background job that the client polls. Runtime validation checks the schema, clue references, evidence count, culprit, timezone consistency, and chronological order. Invalid drafts receive at most two repair attempts.
- **Privacy:** premises and generated case text are stored in MongoDB but are not sent to analytics or logged. Use a private MongoDB deployment with appropriate backups and access controls. Deleting a case removes its database record.
- **Safety:** the generation instructions treat the premise as untrusted fiction, transform real-person references into fictional people, and exclude prohibited content. Every artifact is labeled fictional in the case UI and in its evidence detail.

## API overview

All routes are under `/api/v1` and return `{ data: ... }` or `{ error: { code, message, details? } }`.

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Service health, without internal diagnostics |
| `POST` | `/cases` | Validate a premise and start an idempotent generation job |
| `GET` | `/cases` | Paginated list of the current guest's cases |
| `GET` | `/cases/:caseId` | Case status and playable data; never includes the solution before a guess |
| `PATCH` | `/cases/:caseId/progress` | Record one reviewed evidence item for an owned, active case |
| `POST` | `/cases/:caseId/retry` | Retry a failed generation |
| `POST` | `/cases/:caseId/guess` | Submit the one final suspect selection and receive the reveal |
| `DELETE` | `/cases/:caseId` | Delete an owned case |

## Gemini model choice

The default is `gemini-3.8-flash`, configured through `GEMINI_MODEL`. Google’s model documentation lists the 3.8 Flash family and its structured output documentation describes JSON output. Confirm availability for your Google AI project and region before deployment; the model ID can be changed in the environment without changing product routes. See [Gemini models](https://ai.google.dev/gemini-api/docs/models) and [structured output](https://ai.google.dev/gemini-api/docs/structured-output).
